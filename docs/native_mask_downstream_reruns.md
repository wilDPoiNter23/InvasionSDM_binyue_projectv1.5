# Reusing city models after native-domain processing changes

Use the verified `alien_mean` responses from the native-domain comparison. `prepare_city_response_inputs.py` combines the two area-weighted urban zones into a whole-city response and exports the existing GAM input schemas. Predictor fields remain unchanged. These are model-specific input tables: retained legacy outcome classifications, including `risk_class`, are not new classifications.

Run the existing `city_exclusion_sensitivity.R` with updated city responses, the original model definitions and a fresh output directory. Its legacy `ARCHIVED_GAM_RISK` label now identifies the supplied FULL response; retain `response_identity.json` with the results. Do not interpret the unchanged label as evidence that the response is still historical.

`run_city_component_inputs.R` supplies the new continuous responses to the existing `component_formulas`, `component_fit` and cached-bootstrap functions in `paired_response_sem.R`. Equations, unsupervised predictor PCs, standardization and resampling are retained. This is the existing component sensitivity model supplied with continuous responses, not a reproduction of the archived response-weighted composite workflow. `verify_city_model_inputs.R` independently checks whole-city aggregation, unchanged predictors, fitted GAM responses, linear coefficients and bootstrap intervals.

Other suitability-dependent outputs require updated inputs before interpretation: outside-city comparisons, cohort and land-use summaries, species-level hierarchical regressions, threshold-defined suitable area and fraction, mining comparisons and aggregate hotspot classes. Native exclusion is a species-level operation; do not attempt to apply one species mask to an already averaged multispecies surface. Saved fitted SDMs and species-specific threshold values remain reusable. Observation-only regressions, record chronology, human-variable associations and city-selection tables do not depend on the changed suitability surface. A separate decision to require locally non-native observations would require updating the observation inputs as well.

The current city-cell cache does not cover outside-city or global mining domains. Those comparisons need corresponding saved-prediction extraction before the existing statistical scripts can be rerun. No new SDM fitting is implied. The cohort-by-use support is fully covered by the current city-cell cache, so its input extraction can be updated without another raster projection.

`prepare_masked_coastal_inputs.R` updates the saved species-by-zone inputs. The paired models retain the existing 684-species roster; an additional `FULL_814` group uses the complete FULL roster. The Bayesian fitting interface accepts `expected_species_count`, defaulting to 684, and the report interface accepts `model_groups`. Sampling, priors, transformations, fixed effects and crossed/nested random intercepts are unchanged. `prepare_masked_period_inputs.R` reuses the original category polygons and exact fractional-cell spatial weights. Both all-mapped and the previously declared geometry-filtered comparisons are retained.

`prepare_masked_binary_inputs.R` applies the saved T10 and maximum-TSS thresholds with the original inclusive boundary. It records genuine missing predictions and native exclusions separately. Each cell averages binary suitability over finite non-native species. Spatial integration gives an effective suitable area; division by finite spatial area gives its fraction. This is neither the union of suitable habitat nor an observed invaded area. The actual sum of individual species areas is recorded separately. The legacy response-column names are retained for compatibility and must be interpreted together with `response_definition = CELLWISE_NATIVE_EXCLUDED`.

The binary GAM and component interfaces accept this explicitly supplied area response and declared groups without changing their regression equations or transformations. Their default fixed-species mode remains available for archived inputs. The native-excluded mode retains the full supplied roster without requiring a species to have a non-native prediction in every city. FULL-only 814-species and paired 684-species analyses are stored separately. `verify_masked_downstream.R` independently reconstructs model inputs and binary regional values from the saved prediction matrices and species masks, and checks saved posterior summaries. Existing contrast and component verifiers check actual fitted responses, coefficients and bootstrap summaries.

When longer sampling is needed, `coastal_bayes_selected_cases.R` evaluates the existing fitting initialization and calls its unchanged `run_case` function for the declared cases. Warmup and draw counts come from configuration; model equations and case-specific prior settings remain unchanged. Keep longer-chain results in a distinct model directory and retain initial diagnostics. The reporting interface accepts `report_directory` so each run can be summarized without overwriting another run.
